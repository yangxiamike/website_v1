# 2026-05-29 Demo 站点分层与运行入口澄清

## 背景

当前项目同时存在两类站点：

1. 模板自带的完整版演示站，用于持续设计、交互和页面开发。
2. 由 `tools/sitegen/generate.py` 根据 `content/companies/*.yaml` 生成的客户站点，用于验证裁剪资料、缺省字段和多公司输出。

但这两类站点的入口没有被明确区分，导致开发时容易误把 `sites/haiyue/app/` 这种生成站当成主 demo。生成站的数据又比模板 demo 更精简，因此会出现产品、行业数量不一致的混淆。

## 目标

1. 明确“完整版开发 demo”和“裁剪/生成站”的职责边界。
2. 把本地运行入口写清楚，默认开发 demo 指向完整版模板站。
3. 保留现有生成流程，不破坏 `sites/<company-id>/app/` 的验证用途。

## 实施项

1. 新增一份简短文档，说明两类站点的定位、目录和启动方式。
2. 在模板站与生成站的 README 中补充说明，减少误用。
3. 重新启动本地开发服务，切换到完整版模板站验证。

## 验证

1. 本地打开完整版开发 demo，确认首页、产品页、行业页显示完整演示数据。
2. 文档里能明确找到两类站点各自的目录与用途。
